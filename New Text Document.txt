The fix is to send a real JSON body with --input.

Working command

$json = @'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["Build and test", "Container builds"]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null
}
'@
Set-Content -Path protection.json -Value $json -Encoding ascii
gh api -X PUT repos/kopcot/DLNAServer/branches/main/protection --input protection.json
Remove-Item protection.json

Two PowerShell 5.1 details that will bite if they slip: the closing '@ must sit at column 0 with nothing before it, and -Encoding ascii is deliberate — utf8 in 5.1 writes a BOM, which gh rejects as malformed JSON.

If it comes back 403 instead

Classic branch protection on a private repo needs GitHub Pro or Team. Rulesets are the free equivalent and do the same job:

$json = @'
{
  "name": "main protection",
  "target": "branch",
  "enforcement": "active",
  "conditions": { "ref_name": { "include": ["refs/heads/main"], "exclude": [] } },
  "rules": [
    { "type": "deletion" },
    { "type": "non_fast_forward" },
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": true,
        "required_status_checks": [
          { "context": "Build and test" },
          { "context": "Container builds" }
        ]
      }
    }
  ]
}
'@
Set-Content -Path ruleset.json -Value $json -Encoding ascii
gh api -X POST repos/kopcot/DLNAServer/rulesets --input ruleset.json
Remove-Item ruleset.json

One thing either way: run this after CI has completed once on main. Naming a context that has never reported is accepted, but the branch then sits permanently blocked waiting for a check that does not exist yet.
